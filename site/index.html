One MCP server and CLI that gives any coding agent — Claude Code, Codex, Cursor, Gemini CLI — eyes on running software. Battle-tested local tools (strace, py-spy, perf, lsof, tcpdump, gdb/lldb, Node's inspector) do the observing; DEA turns their output into structured evidence: every finding cites evidence ids, every limitation is stated, raw artifacts are kept for audit.

mcp-debugger is for when you know where to put the breakpoint. DEA is for when you don't.

Rolling it out to a team? Adoption flow: one command per developer, one command per repo, evidence in PRs, a CI gate. Plus 10 copy-paste examples.

Ask your agent

“My API gets slow after a few minutes”

profile_cpu → trace_syscalls → inspect_sockets. CPU-bound, or waiting on something — with the frame or the remote named.

“Memory keeps growing”

snapshot_memory ×2 → diff_runs. Exact retained sizes: Array retains 50 MB via Context.retained.

“It's stuck”

dump_stacks. Threads waiting on locks, classified from the source line: worker_ab (app.py:38) [with lock_b:].

“Address already in use”

dea port 8080 → pid, user and command line holding it. DEA never kills it for you.

Real-world situations

EMFILE at 2 am

412 sockets in CLOSE_WAIT behind the load balancer, 980 of 1024 fds. Keep-alive longer than the LB idle timeout.

Disk full, du disagrees

38 GB held by a deleted log file still open on fd 7. logrotate without copytruncate.

Postgres: too many connections

64 connections from one worker, 18× ECONNREFUSED, recvfrom at 91 % of kernel time. No pool reuse.

Celery worker just stops

42 threads blocked acquiring locks, none running, source lines [with lock_b:] / [with lock_a:]. Lock order.

p99 of 1.4 s on one core

9 274 read() calls in 8 s, kernel file copy at 58 % of CPU work. Sync I/O on the event loop.

Pod OOMKilled every few hours

OOMKilled=true, 94 % of the limit, one Array retains 50 MB via Context.retained. Unbounded cache.

Latency spikes every 30 s

212 DNS lookups for one host in 10 s, 127 sockets in TIME_WAIT. No keep-alive, no resolver cache.

EADDRINUSE after a crash

dea port 3000: pid, user and command line of the orphaned dev server. You decide what to kill.

Agents use it on their own

Once set up, the skill and the MCP instructions tell the agent to attach and measure, unprompted, when a command hangs, a test times out, output shows EADDRINUSE / EMFILE / exit 137 / a segfault, or you mention slow, hang, leak or crash. In Claude Code a 40 ms hook spots those signals and nudges the model toward the right tool. Read-only observation needs no permission; packet capture always does. How it works, and the off switch.

Safety

Read-only. 60 s cap per tool, 50 MB raw cap, 16 KB returned to the agent. Never runs sudo — it tells you the command instead. Captures are scoped to the target's ports and require consent. Secrets are redacted in payloads. No cloud, no telemetry. Details.
